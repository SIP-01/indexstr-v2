# Improvement Deep-Dive — SIP-01/indexstr-v2 — 2026-10-21

Archive candidate (v2.1 refresh is final; Crawlstr-v3 absorbed the crawler core but NOT the collections/enrichment layer). Scope: archive-readiness + what to preserve.

## Top recommendations (ranked, with effort S/M/L)

1. **Decide the fate of the collection layer before archiving (M).** This is the only repo where the full indexer stack works out of the box: all 8 curated SQLite collection DBs (~76 MB) committed in `public/collections/`, in-browser read-only SQLite parser (`src/crawler/sqlite.ts`), Blossom SHA-256-verified mirror fallback, deterministic topic enrichment (`enrich.ts`), `SeedProvider` plugin interface, network discovery intake. Crawlstr-v3's `src/crawler/` contains **none** of these (verified via directory listing — no sqlite/collections/enrich/providers files). If v3 is the flagship, either port this layer or make v3 docs point here explicitly as the reference implementation.
2. **Don't repeat the 76 MB-in-git pattern in v3 (S, docs note).** Committing collection DBs fixed the v2.0 "MISSING BINARIES" breakage, but it permanently bloats every clone. The Blossom content-addressed mirror already exists — the sustainable pattern is Blossom-first with integrity verification, thin repo. Record this in v3 docs.
3. **Fix stale links (S).** README ecosystem table + badge point to the old NostrDanish org (`NostrDanish/indxestr`, `NostrDanish/Crwalstr` — both typo'd and migrated). 404s today.
4. **Keep the heartbeat-versioning note (S).** v2.1 fixed heartbeats reporting `v:"1"` on v2 software via `HeartbeatConfig.nodeVersion` (`v:"2"` + `source=indexstr/v2`). This generation-distinguishability rule should be a written convention in the SIP-01 spec repo so v3+ nodes don't regress it.
5. **Add archive banner (S).**
